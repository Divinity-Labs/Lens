PROBLEM SUMMARY
---------------
Four long-standing issues were fixed in this branch. Issues #113 (per-network
config) was already landed upstream before this change; #209 (candles mixing
testnet/mainnet price points), #271 (undocumented error responses / no shared
error schema), and #270 (missing OpenAPI response examples with capture dates)
are implemented here.

1. #113 - Per-network config (already landed, no changes in this PR)
   The config restructure lives in a prior commit and is NOT modified here.
   Full details are documented in src/config.ts (NetworkConfig type, the
   networks.testnet/mainnet getters, env-var naming, and the
   getNetworkConfig(network) selector). It is listed for reference and to
   keep this PR scope explicit.

2. #209 - Candles aggregating testnet and mainnet price points into the same
   candle
   - src/routes/candles.ts
     * Resolved the request network via req.network ?? activeNetwork
       (req.network is declared by src/middleware/network).
     * Added AND network = $3 to the price_points WHERE clause so each
       (pair_key, network) stays in its own GROUP BY bucket.
     * Response now echoes network as testnet or mainnet, mirroring the
       #308 fix for /price/:assetA/:assetB/history.
   - src/api/schemas.ts
     * New candlesResponseSchema (required: pairKey, network, interval,
       from, to, candles) so dev/test request validation and any OpenAPI
       generator see the new field.
   - src/__tests__/candlesNetwork.test.ts (new)
     * Seeds both networks through the real registerNetworkSelector at one
       pair_key with far-apart prices per network, boots the app, and asserts
       every candle respects its own network boundary and the fallback.
     * Also pins the active-network fallback path.
   - openapi.yaml / openapi.json
     * /candles/{assetA}/{assetB} now declares a network query parameter
       (enum testnet|mainnet) and a network response field.
   - README.md
     * Moved /candles/:assetA/:assetB from the ignore-parameter list to
       the per-request list where the spec places it.

3. #271 - Undocumented route error responses; no shared error schema
   - openapi.yaml
     * One shared component components.schemas.Error with stable keys
       (error, optional message, code).
     * components.responses.BadRequest, Unauthorized, NotFound, Conflict,
       PaymentRequired, TooManyRequests, and InternalServerError reference
       #/components/schemas/Error (no inline copies).
   - src/routes / src/api / contract edges
     * Every public route lists its real error statuses (400, 401, 402, 404,
       409, 429, 500 as applicable). The x402 Verify and Settle routes carry
       their domain schemas but ref the shared 401/429 components.
   - tests/openapi.test.ts
     * Enforcement checks: the shared Error schema exists and is the only
       body schema; every error status references it; no inline
       type-string error copies survive; every route has at least one
       documented error status.

4. #270 - Missing OpenAPI response examples with capture dates
   - openapi.yaml
     * Every operation (GET/POST/PUT/DELETE as declared) carries a realistic
       request/response example plus a captured timestamp (ISO 8601).
     * DELETE /webhooks/{id} is the one 204-no-body exception; its capture
       date is documented verbatim in the 204 response description.
     * Values are sourced from the repos golden fixtures or schema constants
       (seed issuers, pool IDs, history rows, error reason enums); no invented
       contract IDs and no elided short IDs.
   - openapi.json
     * Regenerated with npm run openapi:gen (scripts/generate-openapi.ts).
     * Verified byte-identical to the round-trip of openapi.yaml so the
       generator/regex are stable and future regenerations will not drift.TECHNICAL NOTES
